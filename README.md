# مشروع Smallwebserver

واجهة عربية بسيطة تُقدَّم بواسطة خادم Yaws المكتوب بلغة Erlang.

## بنية المشروع

- `site/`: ملفات الموقع التي تعدّلها، وتشمل صفحات HTML والتنسيق المشترك.
- `yaws-yaws-2.3.1/`: مصدر خادم Yaws وملفات البناء.
- `yaws-yaws-2.3.1/_inst/`: نسخة Yaws المثبتة محليًا؛ لا تعدّل صفحات الموقع داخلها مباشرة.

## تحديث الموقع

من مجلد المشروع الرئيسي، نفّذ:

```sh
bash sync-site.sh
```

ينسخ الأمر محتويات `site/` إلى مجلد الويب الفعلي في تثبيت Yaws. إذا كان الخادم يعمل، حدّث الصفحة في المتصفح؛ وإلا شغّله مرة واحدة:

```sh
cd yaws-yaws-2.3.1
./_inst/bin/yaws --daemon --heart
```

افتح [http://127.0.0.1:8000/](http://127.0.0.1:8000/). بعد أي تعديل على `site/`، أعد تنفيذ `bash sync-site.sh`.

## مراقبة النظام

توجد لوحة المراقبة في `/monitor.html`. تقرأ endpoint في `site/metrics.yaws` بيانات CPU والذاكرة من `/proc`، ونشاط الأقراص من `/sys/block`، وتحدّث الواجهة كل ثانية. لذلك تحتاج إلى Linux وصلاحية قراءة هذه المسارات.

زمن الاستجابة المعروض بوحدة ns هو مدة طلب المؤشرات من المتصفح والعودة، أما زمن جمع البيانات فيُقاس داخل Erlang بساعة monotonic. وحدة ns لا تعني أن دقة المتصفح أو زمن استجابة القرص فعليًا نانوثانية.

endpoint المؤشرات غير محمي بتسجيل دخول؛ أي شخص يستطيع الوصول إلى الخادم يستطيع قراءة هذه البيانات. لا تعرضه على شبكة غير موثوقة قبل تقييد الوصول في إعداد Yaws.

## تشغيل على جهاز Linux فعلي

لجمع بيانات جهازك نفسه، انقل أو استنسخ المشروع عليه، ثم ثبّت Erlang/OTP 25 أو أحدث ومتطلبات البناء. على Ubuntu أو Debian:

```sh
sudo apt update
sudo apt install build-essential autoconf automake libtool libpam0g-dev erlang erlang-dev erlang-xmerl
```

من مجلد المشروع شغّل:

```sh
bash run-on-linux-device.sh
```

يبني السكربت Yaws على الجهاز، يثبت النسخة المحلية، ينشر الموقع، ثم يشغّل الخادم. افتح `http://127.0.0.1:8000/monitor.html` على الجهاز نفسه. السكربت خاص بـ Linux لأن endpoint يعتمد على `/proc` و`/sys`؛ لا يمكنني تشغيله على حاسوبك الشخصي من بيئة Codespaces البعيدة.
